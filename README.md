# 桌面归纳器

> 项目最初创建于 GitHub 仓库 `hello-1`，现已更新为第一版 macOS 桌面归纳器。

macOS 15+ 原生桌面文件整理工具。本机应用位于 `dist/DesktopOrganizer.app`。
`DesktopOrganizerProbe.app` 是早期桌面兼容性验证版，不是日常使用入口。

## 第一次使用

1. 打开 `DesktopOrganizer.app`，在“设置”中选择并授权你的桌面目录。
2. 添加一个或多个“项目总目录”；其中的直属真实子文件夹会成为投递目标。
3. 在系统设置的“桌面与程序坞 → 显示项目”中，按需关闭“在桌面上”。
4. 回到桌面，各类文件会出现在对应看板中。没有文件的看板自动收起。

分类展示不会移动文件。看板可以拖动、调整大小，位置会保存。
桌面最多显示四类看板：固定文件夹、临时文件夹、图片与音视频、文件；空看板不显示。
图片、音频和视频集中在“图片与音视频”看板。
Word、Excel、PPT、PDF、压缩包及其他非媒体文件都在“文件”看板。
看板使用图标网格展示；图片有缩略图，其他项目使用系统图标。图标左上角用于选择，
双击打开，右键可预览、在 Finder 中显示或调整文件夹分类。
看板标题栏右侧的箭头可独立收起或展开；收起后只保留标题栏，状态和原来展开时的大小
都会保存。
菜单栏四格图标中可使用“统一看板大小”，将当前展开看板整理为相同尺寸，同时避免重叠。
控制中心的“桌面文件”页面可在同一看板内拖动文件或文件夹调整显示顺序；
桌面看板会同步更新，重启后仍保留。搜索或仅显示可归档项目时暂不允许调整顺序。
可在控制中心“设置 → 看板名称”中修改四个看板的显示名称；名称不会改变分类规则、
文件路径或投递时的按类型目录名称。
设置中的“看板外观”可切换主题、图标大小、透明度和每个看板的颜色；这些设置只影响显示，
会在本机保存。
新文件夹默认进入“临时文件夹”。右键可设为固定或改回临时；
在控制中心“桌面文件”页选中多个文件夹，可点击“设为固定文件夹”批量分类。
混合选中的图片和其他文件不受该操作影响。分类不移动文件，也不改名。
固定文件夹不计入归档提醒、预检会阻止投递；需要投递时先改为临时。
分类按文件夹身份保存，重启、改名或新增内部文件不改变分类。
菜单栏的四格图标可以打开控制中心、显示看板、投递选中项或退出。
关闭控制中心窗口不会退出应用。

## 浏览与归档

- 双击文件打开；点文件前的圆形选择框进行多选。
- 在看板选中文件后按空格进行 Quick Look 预览，或使用右键菜单。
- 文件可以拖出到其他应用；搜索框搜索桌面文件名。
- 选择文件后点投递，选择项目，再选择“按类型分放”或“指定文件夹”。
- 指定位置可以是项目根目录、已有子文件夹，也可以输入新子文件夹名称。
- 点“预检目标位置”，查看每项真实目标路径、冲突和不可移动原因。
- 点“确认投递”，再次确认后才真正移动文件。结果显示在操作历史。
- 历史支持撤销单项或整批。原位置冲突、目标内容或身份变化时不会强行撤销。

文件夹整体移动，不拆散内部结构；同名项默认跳过，可选择保留两份。
第一版不覆盖、不合并同名文件夹、不跨卷移动，也不移动顶层符号链接。
项目目录中的链接路径会被拒绝。子文件夹超过两万项时请分批处理。

预检会检查文件是否已在本机、是否是常见下载临时文件、是否在两次检查间变化，
并在移动前再次核对内容。它不能锁住其他应用；归档前应保存并关闭正在编辑的文件。
若目标在预检后突然出现同名项，独占移动操作会拒绝覆盖。

## 归档提示

- 默认从工具首次观察到文件开始计时，满7天标记“可归档”，天数可修改。
- 这不是“未打开时间”。重启应用不会重置计时；离开桌面后再次进入按新一轮计时。
- 每周提醒默认关闭，开启后默认周五20:00，可改星期、小时和分钟。
- 提醒不会移动文件。通知被拒绝时，归档标记仍有效。
- 应用关闭时不保证通知；启动或唤醒后最多补发一次最近到期的提醒。

## 退出与恢复

如需停用看板，退出应用后，在系统设置中重新开启“在桌面上”，原文件图标就会恢复。
即使应用异常退出，也可用同样方法恢复。工具不会自动修改 Finder 设置。

本地记录位于 `~/Library/Application Support/DesktopOrganizer/`。
其中保存目录授权书签、文件观察时间、布局、设置和投递日志，不保存文件内容副本。
不要在应用运行中删除该目录；删除它会丢失历史和撤销依据，但不会删除真实文件。
文件操作中不允许正常退出；异常退出后会核对未完成记录，不会自动重试或删除文件。
状态不明的记录会标为“需人工核对”，可从历史分别打开原位置和目标位置。
撤销不会自动删除已创建的空分类文件夹。

## 构建与测试

要求 Swift 6.2 命令行工具，使用系统 AppKit、SwiftUI、SwiftData、Quick Look，无第三方依赖。
本机产物针对 Intel 架构。Apple 芯片及其他系统版本需另行构建和实机验证。

```sh
zsh scripts/test.sh
zsh scripts/test-persistence.sh
zsh scripts/build-app.sh
open dist/DesktopOrganizer.app
```

SwiftData 使用公开 PersistentModel 接口，避免依赖本机 CLT 缺少的代码生成插件。
同一存储在进程内共享模型上下文；三进程测试独立验证实际磁盘持久化，
不能只以同一进程中的读取结果作为落盘成功依据。

## 隔离示例验证

示例模式只接受脚本生成、带专用标识的全新目录，不应指向真实桌面。
命令中的目录已存在时，脚本会拒绝覆盖。

```sh
swift scripts/make-assets.swift .build/demo-assets .build/new-demo
open dist/DesktopOrganizer.app --args --demo-root "$PWD/.build/new-demo" --self-test
```

示例模式会在测试目录执行文件新增、改名、移除、两轮投递和撤销。
结果位于该目录的 `AppData/qa-result.json`，示例数据与正式用户数据完全分开。
退出示例模式后，正常双击应用即可进入真实目录授权流程。

## 发布边界

当前是本机使用版本，只有 ad-hoc 本地签名，未完成 Developer ID 签名或公证。
给其他用户试用前，需要 Apple Developer Program 会员、稳定的发布标识、相应架构构建、
Hardened Runtime 签名及公证，并测试授权、通知、升级和不同显示环境。
开发者账号密码和证书私钥不得放入项目或聊天。

验证记录见 `docs/verification-2026-09-27.md` 和 `docs/release-validation.md`。
